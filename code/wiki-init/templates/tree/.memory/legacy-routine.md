# Legacy social routine compatibility

This optional project workflow is enabled by an existing `.memory/tracker.md`.
Fresh memory installations do not create that file or enable this workflow.
The `structural.py tracker` and `tracker-log` commands retain their existing format,
item names (`connects`, `comments`, `post`, `threads_post`), daily grading, blocked
runs, streaks and weekly post targets. Existing tracker data is never rewritten by
installation or update.

When the tracker exists, resume includes its computed daily report and STATE retains
the legacy rule against retelling routine scores in prose. Keep those scores in the
tracker. This historical heuristic is specific to this workflow; generic projects
use only the canonical STATE headings and line budget. Queue run discovery remains
available for existing queue files. New projects need no routine-specific setup.

Overview field names belong to the project. Keep its existing names when editing;
choose suitable fields for a new overview instead of copying another project's
social or conversion vocabulary. Memory lookup reminders apply to the wiki;
project code search uses the tools actually available in that project.
